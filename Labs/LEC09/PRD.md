# Sonic 애니메이션 뷰어 PRD

## 1. 문서 목적

`PRE-PRD.md`와 LEC09 실습 자료를 구현 가능한 제품 요구사항과 검증 기준으로 구체화한다. 구현은 Python과 `pico2d`를 사용한다.

## 2. 제품 개요

| 항목 | 내용 |
| --- | --- |
| 제품명 | Sonic 애니메이션 뷰어 |
| 구현 파일 | `Labs/LEC09/sonic_animation_viewer.py` |
| 렌더링 라이브러리 | `pico2d` |
| 입력 에셋 | `Labs/LEC09/sonic-sprite.png` (399×525 픽셀, RGBA) |
| 캔버스 | 1200×800 픽셀 |
| 사용자 | 스프라이트 애니메이션을 실행하고 확인하는 개발자 및 수업 참여자 |

## 3. 목표와 동작 요약

뷰어는 시트에 정리된 10종의 동작, 총 76프레임을 순서대로 재생한다. 각 동작을 9회 반복하고 마지막 프레임과 캐릭터 위치를 1초 유지한 뒤 다음 동작으로 이동한다. 동작 8종은 애니메이션과 동시에 캐릭터 위치가 움직이고, 회전 진입 동작과 포즈 동작 2종은 화면 중앙에서 재생한다. 마지막 동작 뒤에는 첫 동작으로 돌아가 이 순서를 반복한다. 프레임은 원본 크기의 4배로 표시한다.

## 4. 사용자 흐름

1. 사용자가 `Labs/LEC09`에서 뷰어를 실행한다.
2. 뷰어가 스크립트 위치를 기준으로 `sonic-sprite.png`를 불러온다.
3. 1200×800 캔버스에서 첫 동작을 재생하며 캐릭터를 4배 크기로 그린다.
4. 현재 동작을 9회 재생한다. 이동 동작이면 프레임이 재생되는 동안 캐릭터도 함께 이동한다.
5. 마지막 프레임과 위치를 1초 유지한 뒤 다음 동작을 시작한다.
6. 열 번째 동작 뒤 첫 동작부터 전체 순서를 다시 재생한다.
7. 창 닫기 또는 Escape 입력으로 프로그램을 종료한다.

## 5. 기능 요구사항

### FR-1. 캔버스와 에셋

- 게임 캔버스 크기는 1200×800 픽셀이다.
- `sonic-sprite.png` 경로는 현재 작업 디렉터리가 아니라 스크립트 파일의 위치를 기준으로 계산한다.
- 에셋을 읽을 수 없으면 파일 경로를 포함한 오류를 출력하고 종료한다.
- 종료 시 게임 창과 이미지 리소스를 정리한다.

### FR-2. 프레임 데이터

- 10개 동작을 코드에서 식별 가능한 순서로 정의하고, 프레임 수의 합은 76이어야 한다.
- 동작별 프레임 사각형은 아래 표의 원본 이미지 좌상단 기준 `(x, y, width, height)` 좌표를 사용한다. 표의 사각형은 투명 여백을 제외한 캐릭터 픽셀 경계다.
- `pico2d`의 클리핑 좌표는 이미지 하단 원점이므로 원본 이미지 높이 525를 사용해 `bottom = 525 - y - height`로 변환한다.
- 프레임별 기준점(offset)을 사용해 프레임 크기가 바뀌어도 캐릭터의 발 또는 몸 중심이 불필요하게 흔들리지 않도록 한다.
- 프레임 메타데이터와 재생·이동 로직을 분리한다.

### FR-3. 프레임 애니메이션과 동작 순환

- 각 동작은 표에 정의된 프레임 순서대로 재생한다.
- 한 동작의 프레임 시퀀스를 완료할 때마다 반복 횟수를 1 증가시키고, `ACTION_REPEAT_COUNT = 9`회 완료하면 동작을 전환한다.
- 동작 전환 시 마지막 프레임과 현재 위치를 1초 동안 유지한다. 이 시간에도 이벤트 처리를 계속한다.
- 열 번째 동작 다음에는 첫 동작으로 돌아간다.
- 프레임 시간 간격은 초 단위 상수로 관리하고 실제 경과 시간을 기준으로 갱신한다.

### FR-4. 캐릭터 출력 및 이동

- 프레임은 가로·세로 모두 원본 대비 4배 크기로 그린다.
- 캐릭터는 캔버스 경계 안에서 보이도록 배치한다.
- 이동이 지정된 8개 동작은 프레임 갱신과 별도로 시간 기반 위치 갱신을 수행해 애니메이션과 이동이 동시에 일어나게 한다.
- 이동 동작 중 캐릭터가 캔버스 경계에 닿으면 이동 방향을 반전해 화면 안에서 계속 움직이게 한다.
- 회전 진입 동작과 포즈 동작 2개는 화면 중앙에서 재생하며 이동하지 않는다.
- 점프 동작은 시간에 따른 상승·하강 궤적을 사용한다.
- 1초 정지 중에는 마지막 프레임과 위치를 유지한다.
- 동작별 이동 경로와 화면상의 재생 위치는 아래 개발 단계에서 시트의 동작을 확인해 확정하고 기록한다.

### FR-5. 이벤트 처리

- 창 닫기 이벤트와 Escape 키로 프로그램을 종료할 수 있다.
- 애니메이션 재생, 이동, 1초 대기 중에도 이벤트를 처리해 종료 입력에 응답한다.

## 7. 비기능 요구사항

- 실행 코드는 `sonic_animation_viewer.py` 한 파일로 제공한다. PNG 에셋은 별도 파일이다.
- `pico2d` 이외의 애니메이션 또는 GUI 프레임워크를 추가하지 않는다.
- 캔버스 크기, 배율, 프레임 시간, 반복 횟수, 정지 시간, 이동 속도는 상수로 쉽게 조정할 수 있게 정의한다.
- 초기화, 이벤트 처리, 상태 갱신, 그리기, 종료가 명확히 구분된 게임 루프 구조를 사용한다.
- 개발은 의미 있는 작은 단계로 진행하고 전체 과정에서 최소 20개의 실제 기능·문서·검증 커밋을 남긴다. 모든 커밋 메시지는 한글로 작성한다. 의미 없는 변경으로 커밋 수를 채우지 않는다.

## 8. 단계별 개발 계획

| 단계 | 결과물 | 확인 사항 |
| --- | --- | --- |
| 1. 실행 기반 | 단일 Python 파일, pico2d 초기화/종료, 1200×800 캔버스, 스크립트 상대 에셋 경로 | 파일이 실행되고 창 닫기와 Escape가 동작 |
| 2. 프레임 출력 | 4배 출력, 중심/기준점 처리, 좌표 변환 | 선택 프레임들이 잘림 없이 올바른 위치에 표시 |
| 3. 애니메이션 메타데이터 | A01–A10, 총 76개 프레임 사각형 및 순서 | 동작별 수 합이 76이고 모든 좌표가 시트 범위 안에 있음 |
| 4. 동작 재생 상태 | 프레임 시간 갱신, 동작별 9회 반복, 1초 마지막 프레임 유지, 전체 순환 | 순환 경계와 반복 횟수가 정확하고 정지 화면이 유지됨 |
| 5. 이동 구현 | 이동 동작 8종의 시간 기반 경로, 경계 반전, 점프 궤적, 중앙 고정 동작 2종 | 프레임 재생과 이동이 함께 진행되고 경계에서 방향이 바뀜 |
| 6. 통합 및 문서화 | 예외 처리, 실행 안내, 최종 수용 기준 확인 | 실행 위치에 관계없이 에셋 로딩 및 정상 종료 확인 |

각 단계는 더 작은 검토 가능한 변경으로 나눠 커밋한다. 전체 최소 20회 커밋 목표를 지키고, 모든 커밋 메시지를 한글로 작성하며 각 커밋에는 실제 변경과 확인 결과를 남긴다.

## 9. 검증 및 수용 기준

### 정적·데이터 검증

- [ ] `sonic_animation_viewer.py`가 Python 문법 검사를 통과한다.
- [ ] 등록 동작 수가 10이고 동작별 프레임 수 합이 76이다.
- [ ] 모든 `(x, y, width, height)`가 양수 크기이며 `0 ≤ x`, `0 ≤ y`, `x + width ≤ 399`, `y + height ≤ 525`를 만족한다.
- [ ] top-origin 좌표에서 pico2d bottom-origin 좌표로 변환한 값이 올바르다.
- [ ] 실행 위치를 바꿔도 스크립트 기준으로 PNG를 찾는다.

### 재생 로직 검증

- [ ] 동작마다 프레임 순서가 유지되고 정확히 9회 재생한 뒤 전환한다.
- [ ] 각 전환 시 1초 동안 마지막 프레임과 캐릭터 위치가 유지된다.
- [ ] 열 번째 동작 다음에 첫 동작으로 돌아간다.
- [ ] 이동 8종에서 캐릭터 위치가 애니메이션과 동시에 시간에 따라 변한다.
- [ ] 이동 동작은 캔버스 경계에서 방향을 바꾸고 화면 밖으로 사라지지 않는다.
- [ ] 중앙 고정 2종은 재생 내내 화면 중앙에 유지되며, 점프 동작은 상승 후 하강한다.

### 화면·종료 검증

- [ ] 창 크기가 1200×800이고 캐릭터 출력 배율이 원본의 4배다.
- [ ] 각 프레임이 화면에 올바르게 잘려 나오며 불필요한 프레임 간 위치 흔들림이 없다.
- [ ] 실제 창에서 모든 동작의 순환과 정지 구간을 육안으로 확인한다.
- [ ] 창 닫기와 Escape가 애니메이션 및 정지 중 모두 정상 종료한다.
- [ ] 의미 있는 개발 커밋이 최소 20개이며 로그에서 단계별 변경 내용을 확인할 수 있다.
- [ ] 모든 개발 커밋 메시지가 한글로 작성되어 있다.

문법 검사, 데이터 검사, 시간 기반 로직 확인, 실제 창 시각 확인은 서로 다른 증거로 기록한다. 프로그램이 시작된다는 사실만으로 모든 프레임 좌표와 움직임이 올바르다고 판단하지 않는다.

## 10. 범위 제외

- 사용자 입력으로 동작을 선택하거나 재생을 일시 정지·속도 조절하는 기능

- 외부 설정 파일, 네트워크 기능, 별도 GUI 프레임워크
- 여러 캐릭터나 복수 스프라이트 시트 지원
